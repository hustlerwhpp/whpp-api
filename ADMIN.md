# Админка WHPP API

Кабинет клиента — `/`, админка — `/admin`.

## Как это работает

- Клиенты хранятся в переменной окружения `CLIENTS_MAP` (JSON):
  `{ "<код доступа>": { "name": "Имя", "orderCode": "<код заказа triklz>" } }`.
  Других баз нет: на serverless файловая система эфемерна.
  Карта хранится как encrypted-переменная, админка читает её через API
  с `decrypt=true` — без этого Vercel отдаёт шифротекст, и список пуст.
- Админ входит в `/admin` по паролю из `ADMIN_PASSWORD` и создаёт/удаляет
  клиентов и меняет им коды. Админка сама переписывает `CLIENTS_MAP` через
  API Vercel и запускает редеплой — код и кнопку Deploy трогать не надо.
- Клиент входит по своему коду доступа и видит только свой баланс, ключ,
  модели и историю. Сессия — httpOnly-cookie, код в localStorage не хранится.
- Изменения вступают в силу после редеплоя (~минута). Если клиент попробует
  войти по новому коду раньше, увидит «идёт редеплой — попробуйте через минуту».

## Env (Vercel → Project → Settings → Environment Variables, Production+Preview)

| Переменная | Зачем |
|---|---|
| `CLIENTS_MAP` | Карта клиентов (уже есть) |
| `UPSTREAM_API_URL` | Адрес upstream triklz (уже есть) |
| `PROXY_BASE_URL` | Cloudflare Worker для прокси (уже есть) |
| `ADMIN_PASSWORD` | Пароль админа для `/admin` |
| `VERCEL_TOKEN` | Токен аккаунта Vercel (Full Account) — им админка правит `CLIENTS_MAP` и запускает редеплой |
| `VERCEL_PROJECT_ID` | Id проекта (Settings → General) |
| `VERCEL_TEAM_ID` | Опционально, если проект в команде |
| `VERCEL_DEPLOY_HOOK_URL` | Опционально, хук деплоя вместо API деплоя |

Без `VERCEL_TOKEN`/`VERCEL_PROJECT_ID` админка откроется и покажет клиентов,
но создание/удаление вернёт ошибку — сначала задайте эти две переменные
и сделайте редеплой.
